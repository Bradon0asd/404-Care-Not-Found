# Progress

整理目前的開發工作進度，產出 `outputs/current_progress.md`。

## 執行步驟

1. 讀取現有的 `outputs/current_progress.md`（若不存在則視為首次執行，版本號從 v1 起算）。
   取出其中最大的版本號，本次記錄的版本號為該值 +1。

2. 執行以下指令，取得目前 git 狀態與近期變更記錄：
   - `git status` — 列出所有已修改、新增、未追蹤的檔案
   - `git diff --stat HEAD` — 統計各檔案的變更量
   - `git log --oneline -10` — 最近 10 筆 commit

3. 掃描 `outputs/` 目錄，列出所有已產出的檔案及其最後修改時間。

4. 根據當前對話內容與上述指令結果，整理本次進度報告，內容涵蓋：
   - **目前正在做什麼任務**：本次工作的主要目標
   - **已修改的檔案**：來自 git status / diff，標注新增(A) / 修改(M) / 未追蹤(?)
   - **還有哪些事情沒做完**：根據對話脈絡與任務目標，列出待完成事項
   - **測試結果**：若有執行過任何 Skill 或產出任何檔案，記錄執行結果（成功 / 失敗 / 部分完成）

5. **套用歷史保留規則**（見下方「歷史保留規則」），把舊版本記錄整理成該保留的樣子。

6. 將報告寫入 `outputs/current_progress.md`，格式如下：

```
# Current Progress

> 最後更新：[timestamp]　｜　版本：v[N]

---

## 目前任務

[一句話描述正在進行的工作]

---

## 已修改的檔案

| 狀態 | 檔案路徑 | 說明 |
|:---|:---|:---|
| A（新增） | path/to/file | ... |
| M（修改） | path/to/file | ... |
| ?（未追蹤） | path/to/file | ... |

---

## 待完成事項

- [ ] ...
- [ ] ...

---

## 測試 / 執行結果

| Skill / 操作 | 結果 | 備注 |
|:---|:---|:---|
| /guide-parser | ✅ 成功 | 產出 outputs/Submission_Guide.md |
| /chart-reviewer | ⏳ 尚未執行 | — |

---
---

# 歷史記錄

## 詳細記錄

### v[N-1] — [timestamp]

**任務**：[一句話]

**已修改的檔案**

| 狀態 | 檔案路徑 | 說明 |
|:---|:---|:---|
| ... | ... | ... |

**待完成事項**

- [ ] ...

**測試 / 執行結果**

| Skill / 操作 | 結果 | 備注 |
|:---|:---|:---|
| ... | ... | ... |

### v[N-2] — [timestamp]

（同上格式，依序到 v[N-4]）

---

## 歷史摘要

- v[N-5]（[日期]）：[一行說明]
- v[N-6]（[日期]）：[一行說明]
- ...
```

7. 回報：已將進度報告寫入 `outputs/current_progress.md`，並簡述關鍵待完成項目。
   若本次有版本被壓縮成一行，一併說明壓縮了哪幾個版本。

## 歷史保留規則

`current_progress.md` 每次執行都會累積一筆記錄，不加控制會無限成長，因此：

- **含本次在內，最新 5 個版本保留完整內容**。也就是「目前任務」區塊（v[N]）加上
  「詳細記錄」區塊裡的 v[N-1] 到 v[N-4]，共五次。
- **第 6 個（含）以前的版本壓縮成一行**，移入「歷史摘要」，格式：

  ```
  - v7（2026-08-10）：完成六校系所過濾規則，PDF 下載模組尚未開始
  ```

  一行的內容取「該版本做完了什麼」＋「當時最主要的未完成項目」，其餘（檔案清單、
  勾選框、測試表格）全部丟棄。

- **歷史摘要依版本號由新到舊排列**，不設上限（一行的成長速度可以接受）。
- **壓縮是單向的**：已壓成一行的版本不會再展開。若日後需要查完整內容，
  看 `outputs/current_progress.md` 的 git 歷史（前提是該檔有進版控）。
- 版本號**只增不減**，不因壓縮而重新編號——否則歷史摘要裡的 v 編號會對不上。
